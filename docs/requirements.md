## 0. この文書の読み方

- DCS World のミッションファイル（`.miz`）を読み込み、ブリーフィング資料を素早く作る Web ツール **FastBriefing** の要件を定める。
- 事実として書いていることは、実ファイルの解析か一次ソースで確認したもの。未確認のものは **要検証** と明記した。
- 優先度は MoSCoW（**MUST** / **SHOULD** / **COULD** / WON'T）で表す。フェーズは §9 のロードマップに対応する。
- 決めきれないことは §11「未決事項」にまとめた。それ以外は前提（§1.4）を置いて先に進める。

## 1. 背景と目的

### 1.1 現状の課題

- ブリーフィングのたびにミッションエディタ（ME）を開いて経路や周波数を確認している。参加者全員が ME を開けるわけではなく、口頭説明の負担が大きい。
- 既存ツールには穴がある。CombatFlite は Windows 専用で開発状況が不明。Combined Ops や DCS MDC Builder は Web だがクローズドソースで、ミッションファイルをサーバへ送る必要がある。DCS Web Editor は「オープンソース化」を告知したがリポジトリは消えている。
- 手元のミッションは改版が多い（`pagan → paganNeo → paganNeoNEO`、`0124002 → Remake0124002` など）。改版のたびに「何が変わったか」を説明し直す手間がある。

### 1.2 目的

**「.miz をブラウザにドロップして、10 秒後にはブリーフィングを始められる」** 状態を作る。

- ミッション作成者は資料作りの時間をゼロに近づける。
- フライトリードは自分のフライトのカードを印刷・ニーボード化して機内に持ち込める。
- 参加パイロットは PC でもスマホでも同じ資料を見られる。

### 1.3 成功基準（v1.0 完成の定義）

| # | 基準 | 測り方 |
|---|---|---|
| G1 | 手元の実ミッション 19 本すべてがエラーなく読み込め、概要・フライト・経路・通信が表示される | フィクスチャによる自動テスト |
| G2 | 変換した緯度経度が ME の表示と一致する | Phase 0 で ME 表示と目視照合。許容誤差は照合結果を見て決める |
| G3 | 1 フライト分の資料一式（概要・ナビログ・コムカード・地図）を 3 操作以内で PDF と PNG に出せる | 手動受け入れテスト |
| G4 | Windows と Linux の両方で、同じ手順で起動できる | CI で両 OS のビルドとテストを回す |
| G5 | ミッションファイルの中身が既定ではユーザーの PC から外に出ない | ネットワーク監視で確認 |

### 1.4 前提（仮定）

| # | 前提 | 根拠・備考 |
|---|---|---|
| A1 | 主な利用者は日本語話者の DCS マルチプレイ（COOP）コミュニティ。UI は日本語を第一、英語を第二とする | 手元ミッションは Client スロット 7〜60 の COOP 構成 |
| A2 | 初期の対象マップは Caucasus と Marianas。他マップは投影パラメータの追加で対応する | 手元ミッションはこの 2 マップのみ |
| A3 | 初期の対象機種は手元ミッションに登場する機種（§付録 A）。機種固有の座標形式はこの範囲から優先実装する | |
| A4 | オープンソース（MIT 想定）で公開し、静的ホスティングとローカル起動の両方をサポートする | §11 で確認 |
| A5 | DCS 純正 DTC への書き出しは v1 の範囲外とし、調査項目として残す | 形式が未公開。§5.11 参照 |

## 2. 利用者と利用シーン

### 2.1 利用者

| 役割 | 主な行動 | 求めるもの |
|---|---|---|
| ミッション作成者（ホスト） | `.miz` を読み込み、資料を配布し、改版する | 手間ゼロの資料化、改版差分、ネタバレ制御 |
| フライトリード | 自分のフライトの計画を確認し、口頭でブリーフィングする | ナビログ、コムカード、燃料の目安、プレゼン表示 |
| パイロット | 配布資料を読み、機内でニーボードとして使う | 機種に合った座標形式、読みやすいカード、スマホ表示 |
| GCI / JTAC（将来） | 全体の空域と地上目標を把握する | 全フライトの俯瞰、脅威、目標座標 |

### 2.2 利用シーン

| # | シーン | 必要な機能 |
|---|---|---|
| S1 | セッション前に Discord へ資料を投稿する | Markdown / 画像出力、共有リンク（将来） |
| S2 | セッション直前に画面共有で口頭ブリーフィングする | 地図、プレゼンモード、フライト切替 |
| S3 | 機内でニーボードとして参照する | 3:4 の PNG 出力、`.miz` への埋め込み |
| S4 | 改版後に「変更点だけ」を再ブリーフィングする | 差分表示 |
| S5 | 練習ミッションで一人で計画を確認する | ローカル起動、オフライン動作 |

## 3. スコープ

### 3.1 含むもの

- `.miz` の読み込みと解析（ブラウザ内で完結）
- ブリーフィングに必要な情報の閲覧（概要、天候、フライト、経路、通信、支援機、脅威、地図）
- 資料の出力（印刷 / PDF、ニーボード PNG、`.miz` への埋め込み、Markdown、GeoJSON）
- 手入力の注記（SMEAC の文章など）と、その保存・再利用
- Linux / Windows で同じ手順で動くこと

### 3.2 含まないもの（v1）

- ミッションの編集（経路の変更やユニットの追加）。編集は ME の仕事
- ミッション生成（BriefingRoom や Retribution の領域）
- DCS 純正 DTC への書き出し（形式未公開。§5.11 で調査項目として扱う）
- LLM による文章生成（アイデアとして §5.11 に残す。実装するなら明示的なオプトインにする）

## 4. 用語

| 用語 | 意味 |
|---|---|
| `.miz` | DCS のミッションファイル。実体は ZIP。中に `mission`（Lua テーブル）などが入る |
| ME | DCS Mission Editor |
| フライト | ME の「グループ」のうち、プレイヤーが乗る航空機グループ |
| パッケージ | 同じ目的で動く複数フライトのまとまり（本ツールでは利用者が手動で束ねる） |
| Bullseye | 勢力ごとの基準点。位置を「方位 / 距離」で伝えるときの原点 |
| BRAA | Bearing / Range / Altitude / Aspect。相対位置の言い方 |
| ニーボード | 機内で見るチェックリスト・カード。DCS では画像として表示できる |
| DTC | Data Transfer Cartridge。機体に周波数や経路を流し込む仕組み |
| SMEAC | Situation / Mission / Execution / Admin & Logistics / Command & Signal。ブリーフィングの定型構成 |

## 5. 機能要件

### 5.1 入力と解析

| ID | 要件 | 優先度 | Phase |
|---|---|---|---|
| FR-01 | `.miz` をドラッグ＆ドロップまたはファイル選択で読み込める。複数同時読み込みは差分機能（FR-90）で使う | MUST | 1 |
| FR-02 | 解析はすべてブラウザ内で行う。既定ではファイルもその中身もサーバへ送らない | MUST | 1 |
| FR-03 | ZIP を展開し、`mission`、`theatre`、`warehouses`、`options`、`l10n/DEFAULT/dictionary`、`l10n/DEFAULT/mapResource`、`KNEEBOARD/**`、`l10n/DEFAULT/*`（ブリーフィング画像）を取り出す | MUST | 1 |
| FR-04 | `mission` は Lua を **実行せず**、構文木として読み取り JSON に変換する。テーブル・文字列・数値・真偽値・`nil`・コメント以外が現れたら警告して続行する | MUST | 1 |
| FR-05 | `DictKey_*` は `dictionary` で、`ResKey_*` は `mapResource` で解決する。未定義キーは元の文字列のまま表示する | MUST | 1 |
| FR-06 | 未知のキー・未知の機種・未知の兵装が出てもクラッシュせず、「不明」として表示する | MUST | 1 |
| FR-07 | 解析は Web Worker で行い、UI を止めない。進捗を表示する | SHOULD | 1 |
| FR-08 | `warehouses` から飛行場の所属勢力（`airports[id].coalition`。大文字小文字は問わない）を読み取る | SHOULD | 1 |
| FR-09 | 解析結果を正規化した JSON（§8 のモデル）として書き出せる。他ツールとの連携とデバッグに使う | SHOULD | 1 |

### 5.2 座標・単位・時刻の変換

| ID | 要件 | 優先度 | Phase |
|---|---|---|---|
| FR-10 | DCS 座標（`x` = 北向き, `y` = 東向き, 単位 m）を緯度経度に変換する。マップごとの横メルカトル投影パラメータ（pydcs 由来）を用いる | MUST | 0 |
| FR-11 | 対応マップ表にないマップは、緯度経度を出さずに DCS 座標のまま表示し、警告する | MUST | 1 |
| FR-12 | 座標表示形式を切り替えられる。DDM（度・分.分）、DMS（度・分・秒）、MGRS。機種ごとの既定形式を持つ（例: F/A-18C・F-16C は DDM、AH-64D は MGRS、JF-17 は DMS。表は要検証項目を含む） | MUST | 1 |
| FR-13 | 単位を切り替えられる。高度 ft / m、速度 kt / km/h、距離 nm / km、気圧 hPa / inHg / mmHg、温度 °C / °F | MUST | 1 |
| FR-14 | ファイル内の値の意味を正しく扱う。速度は m/s、高度は m、`ETA` はミッション開始からの秒、`start_time` は 0 時からの秒、QNH は mmHg、雲底は m、風速は m/s | MUST | 1 |
| FR-15 | 風向は **ファイル内が「吹いていく方向」** なので、ブリーフィングでは 180° 反転した「吹いてくる方向」で表示する。両方の値を併記できる | MUST | 1 |
| FR-16 | 磁方位を出す。磁気偏差はミッション日付と位置から WMM 系モデル（JS ライブラリ）で計算する。真方位との併記を可能にする | SHOULD | 1 |
| FR-17 | ミッション時刻を現地時刻と UTC（Zulu）で併記する。マップごとの固定 UTC オフセット表を持つ（Germany Cold War は +1 と +2 で資料が食い違うため要検証） | SHOULD | 1 |
| FR-18 | 日の出・日の入り・薄明（航海薄明・市民薄明）・月齢と月照度を、ミッション日付と代表位置（Bullseye または経路重心）で計算する | SHOULD | 1 |

### 5.3 ミッション概要

| ID | 要件 | 優先度 | Phase |
|---|---|---|---|
| FR-20 | ソーティ名、ミッション説明、勢力ごとのタスク文（青・赤・中立）、ブリーフィング画像（`pictureFileName*`）、マップ名、日付、開始時刻、ME バージョンを表示する | MUST | 1 |
| FR-21 | 天候を人が読める形にまとめる。気温、QNH、地上 / 2000 m / 8000 m の風（FROM 表記）、雲プリセットの表示名と雲底、視程、霧、砂塵、乱気流 | MUST | 1 |
| FR-22 | 天候を METAR 風の 1 行にも要約する（例: `27004KT 9999 SCT082 08/M02 Q1018`）。プリセットから雲量への対応は近似であることを明記する | SHOULD | 1 |
| FR-23 | 密度高度や、風の向かい風・横風成分（出発・到着滑走路に対して）を出す | COULD | 2 |
| FR-24 | 表示する勢力（青 / 赤）を選べる。既定は Client スロットが多い方 | MUST | 1 |

### 5.4 フライトとパッケージ

| ID | 要件 | 優先度 | Phase |
|---|---|---|---|
| FR-30 | `skill` が `Client` または `Player` のユニットを含む航空機グループを「フライト」として一覧する。機種、機数、コールサイン、ミッションタスク（CAP / CAS 等）、出発 / 到着飛行場を並べる | MUST | 1 |
| FR-31 | コールサインを解読する。西側機の `callsign` テーブル（`{[1],[2],[3],name}`）は `name` を優先し、東側機の整数コールサインは番号表示にする | MUST | 1 |
| FR-32 | 各機の機番（`onboard_num`）、スキン、スキル、駐機スポットを表示する | SHOULD | 1 |
| FR-33 | 搭載（`payload.pylons[].CLSID`）を兵装名に変換して表示する。燃料量、チャフ / フレア / 機関砲の数、機体総重量の目安を出す | MUST | 1 |
| FR-34 | 無線設定を表示する。グループ周波数と変調、各機の `Radio` プリセット表（チャンネル番号・周波数・変調・名前） | MUST | 1 |
| FR-35 | 機種固有の追加設定（`AddPropAircraft`）のうちブリーフィングに必要なものを表示する。レーザーコード、STN / Link16 設定、音声コールサイン番号、IFF、TACAN、NVG の有無など。未知のキーはそのまま「その他」に列挙する | SHOULD | 1 |
| FR-36 | データリンク（`datalinks`）のメンバー構成（フライトリード、チーム番号など）を表示する | COULD | 2 |
| FR-37 | 複数フライトを手動で「パッケージ」に束ね、パッケージ単位の資料を出せる | SHOULD | 2 |
| FR-38 | ユーザーがフライトごとに Joker / Bingo 燃料、TOT、担当パイロット名などを手入力でき、資料に載せられる | SHOULD | 2 |

### 5.5 経路とナビログ

| ID | 要件 | 優先度 | Phase |
|---|---|---|---|
| FR-40 | フライトごとに経路点の表を出す。番号、名前、種別（`action`）、座標（選択形式）、高度（MSL / AGL、`alt_type` を反映）、速度（TAS kt）、ETA（時刻）、経路点タスクの要約 | MUST | 1 |
| FR-41 | 区間ごとの距離、真方位と磁方位、所要時間、累積距離、累積時間を計算する | MUST | 1 |
| FR-42 | 各経路点の Bullseye 参照（方位 / 距離）を出す | SHOULD | 1 |
| FR-43 | 出発 / 到着 / 代替の飛行場（`airdromeId`、`helipadId`、`linkUnit`）を参照データで名前・位置・滑走路・ATC 周波数に解決する。TACAN / ILS は参照データがある範囲で出し、無ければ「未収録」と示す | MUST | 1 |
| FR-44 | 機体の `NavTargetPoints`（F-15E などのターゲットポイント）を表示する | COULD | 2 |
| FR-45 | 勢力の `nav_points`（ME のナビポイント）を一覧と地図に出す | SHOULD | 1 |

### 5.6 支援機と脅威

| ID | 要件 | 優先度 | Phase |
|---|---|---|---|
| FR-50 | 空中給油機（Tanker タスク）を検出し、コールサイン、周波数、TACAN（`ActivateBeacon`）、高度、速度、軌道（Orbit タスク）を出す | MUST | 1 |
| FR-51 | AWACS（AWACS タスク）を検出し、コールサイン、周波数、軌道を出す | MUST | 1 |
| FR-52 | 空母・揚陸艦を検出し、TACAN・ICLS・Link4 の設定と位置、進路（BRC の目安）を出す | SHOULD | 1 |
| FR-53 | JTAC / FAC を検出し、コールサイン、周波数、レーザーコードを出す | SHOULD | 1 |
| FR-54 | 敵勢力の地上ユニットから SAM / AAA / 早期警戒レーダーを分類し、機種別の脅威半径（参照データの `threat_range`）で地図に脅威リングを描く | SHOULD | 2 |
| FR-55 | 敵の航空機グループ（CAP など）と艦艇を一覧にする。`lateActivation` と `start_time` を出現時刻として示す | SHOULD | 2 |
| FR-56 | ME の `hidden` フラグを尊重する。既定（パイロットビュー）では `hidden = true` のグループを表示しない。作成者ビューでは表示する（FR-70） | MUST | 1 |

### 5.7 地図

| ID | 要件 | 優先度 | Phase |
|---|---|---|---|
| FR-60 | 対話的な地図に、選択したフライトの経路、経路点ラベル、飛行場、Bullseye、ナビポイントを描く | MUST | 1 |
| FR-61 | トリガーゾーン（円・多角形、色）と ME の描画（`drawings`: 線・多角形・テキスト・アイコン、色・線種）を描く | SHOULD | 1 |
| FR-62 | レイヤーごとに表示を切り替えられる（フライト別、ゾーン、描画、脅威、支援機、敵） | MUST | 1 |
| FR-63 | 地図上の任意点をクリックすると、座標（選択形式）と Bullseye 参照が出る。2 点間の距離・方位を測れる | SHOULD | 1 |
| FR-64 | 背景タイルはキー不要のものを既定にし（OpenFreeMap / OpenStreetMap / OpenTopoMap）、利用規約の帰属表示を必ず出す。衛星写真はユーザーが自分の API キーを入れた場合のみ有効にする | MUST | 1 |
| FR-65 | オフラインでもタイルなしで動く。海岸線と国境の簡略 GeoJSON を同梱し、それだけで経路が読めるようにする | SHOULD | 2 |
| FR-66 | 表示中の地図を PNG に書き出せる（資料とニーボード用） | MUST | 2 |

|---|---|---|---|

|---|---|---|---|
| FR-80 | 印刷用レイアウト（印刷 CSS）を持ち、ブラウザの印刷から PDF にできる。A4 縦を基本にする | MUST | 1 |

### 5.10 表示制御と注記

| ID | 要件 | 優先度 | Phase |
|---|---|---|---|
| FR-70 | 「作成者ビュー」と「パイロットビュー」を切り替えられる。パイロットビューでは `hidden` グループ、敵の詳細配置、トリガー条件を出さない。出力もビューに従う | MUST | 1 |
| FR-71 | 自動生成できない文章（状況、意図、緊急時手順など）を編集できる欄を SMEAC の各節に置く | SHOULD | 1 |
| FR-72 | 手入力の内容は `.miz` の識別子（ファイル名と内容ハッシュ）に紐づけてブラウザに保存し、同じミッションを再度開いたときに復元する。サイドカー JSON として書き出し・読み込みもできる | SHOULD | 2 |
| FR-73 | 改版した `.miz` を開いたとき、前版の手入力をグループ名と経路点番号をキーに引き継ぐ | COULD | 3 |

### 5.11 発展機能（アイデア）

## 7. アーキテクチャ方針（推奨案）

### 7.1 全体像

```
.miz (ZIP)
  │ fflate で展開（ブラウザ内 / Web Worker）
  ▼
生ファイル群: mission, theatre, warehouses, options, l10n/DEFAULT/*, KNEEBOARD/**
  │ luaparse で構文木化 → テーブルだけを JSON に変換（コードは実行しない）
  ▼
生 Lua テーブル (JSON)
  │ normalize: DictKey 解決、座標変換、単位変換、コールサイン解読、支援機検出
  │            ◀── 参照データ JSON（投影、飛行場、兵装、ユニット、コールサイン、雲プリセット、UTC）
  ▼
Briefing Model（§8）
  ├─ UI（React）: 概要 / フライト / ナビログ / 地図 (Leaflet) / 通信 / 脅威 / 差分 / プレゼン
  └─ Exporters: 印刷 CSS → PDF、Canvas → PNG（ニーボード）、fflate → .miz 埋め込み、Markdown、GeoJSON
```

### 7.2 技術選定（候補と理由）

| 領域 | 推奨 | 理由 | 却下した案 |
|---|---|---|---|
| 言語・ビルド | TypeScript + Vite | ブラウザ完結、Linux / Windows で同一手順 | Python バックエンド + pydcs（配布が重く、ファイルをサーバへ送る形になる） |
| UI | React | 地図・表ライブラリの選択肢が多い | Svelte / Vue（可。チームの慣れで変更してよい） |
| ZIP | fflate | 小さく速い、Worker 対応、2026 年も更新あり | JSZip（2022 年から更新なし） |
| Lua 解析 | luaparse（AST） | コードを実行しない。テーブル走査だけで済む。更新は 2022 年で止まっているが仕様が安定 | fengari / wasmoon（VM 実行は不要な攻撃面を増やす） |
| 投影 | proj4js + pydcs のパラメータ | pydcs と同じ式で、実ファイルで妥当な結果を確認済み | 独自実装（保守が重い） |
| 地図 | Leaflet | 軽量で実績が多い。タイル差し替えが容易 | MapLibre GL（ベクタタイルを使うなら将来検討） |
| 天文 | suncalc | BSD-2、2026-09 更新 | |
| 磁気偏差 | geomagnetism（Apache-2.0）または geomag（MIT） | 日付を含む WMM 計算。WMM2025 対応は要確認 | 固定値表（BriefingRoom 方式。精度と符号が怪しい） |
| PDF | 印刷 CSS + ブラウザ印刷 | 追加ライブラリ不要。日本語フォントも OS 任せにできる | jsPDF（日本語フォント埋め込みが重い） |
| 画像出力 | Canvas 直描き（または html-to-image） | ニーボードの解像度を固定できる | |
| 任意のサーバー（Phase 3） | Node (Hono) + SQLite、Docker | 解析コードを共有できる | |

### 7.3 参照データの作り方

| データ | 出所 | 生成方法 | 備考 |
|---|---|---|---|
| マップ投影パラメータ | pydcs `dcs/terrain/<map>/projection.py` | スクリプトで JSON 化 | Afghanistan / Iraq は本家に無く、dcs-retribution の fork にある |
| 飛行場（ID、名前、位置、滑走路、ATC 周波数） | pydcs `dcs/terrain/<map>/airports.py` | 同上 | 標高・ICAO・ビーコン周波数は含まれない |
| ビーコン（TACAN / ILS / VOR） | 候補: DCS Web Editor の `Beacons.json`（ライセンス表記なし）、dcs-retribution の `beacons/*.json`（LGPL、座標なし） | ライセンス確認の上で採用。難しければ「ユーザーの DCS インストールから生成するスクリプト」を提供し、再配布しない | §11 の未決事項 |
| 兵装名 | pydcs `dcs/weapons_data.py` | JSON 化 | |
| ユニット（機種、脅威半径、探知距離） | pydcs `dcs/planes.py` `vehicles.py` `ships.py` | JSON 化 | 脅威リングは `threat_range` を使う |
| コールサイン | pydcs `dcs/countries.py` | JSON 化 | |
| 雲プリセット表示名と雲底 | pydcs `dcs/cloud_presets.py` | JSON 化 | 新しい `RainyPreset4-6` 等は実機で確認 |
| UTC オフセット | pydcs `Terrain.utc_offset` と retribution の `info.yaml` | 手動で表を作る | Germany Cold War の食い違いを確認 |

## 8. データモデル（概略）

```
Mission
├─ meta: sortie, description, tasks{blue,red,neutral}, theatre, date, startTime, utcOffset, meVersion, images[]
├─ weather: temperature, qnh{mmHg,hPa,inHg}, wind[{level, from, to, speed}], clouds{preset, label, base}, visibility, fog, dust, turbulence
├─ coalitions[blue|red|neutral]
│   ├─ bullseye {xy, latlon}
│   ├─ navPoints[]
│   ├─ airbases[] {id, name, latlon, owner, runways[], atc[], tacan?, ils?}
│   ├─ flights[] {groupId, name, callsign, type, task, frequency, modulation, hidden, units[], route[]}
│   │    ├─ units[] {unitId, name, tailNumber, skill, livery, payload{pylons[], fuel, chaff, flare, gun}, radios[], props{}, datalink?}
│   │    └─ route[] {index, name, action, xy, latlon, alt, altType, speedMs, eta, tasks[], airdromeId?, leg{distance, trueBrg, magBrg, time}}
│   ├─ support[] {kind: tanker|awacs|carrier|jtac, callsign, frequency, tacan?, icls?, orbit?, position}
│   ├─ aiGroups[] {category, type, count, position, threatRange?, hidden, lateActivation, startTime}
│   └─ zones[] / drawings[]
├─ userNotes {missionKey, smeac{...}, perFlight{...}}
└─ warnings[] (解析時の警告と未対応要素)
```

## 10. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| DCS 更新でミッション形式のキーが増減する | 解析エラー | 未知キーを許容する設計（FR-06）、フィクスチャを DCS 更新ごとに追加 |
| Afghanistan / Iraq などの投影パラメータが本家 pydcs に無い | 該当マップで緯度経度が出ない | retribution fork から取り込む。無いマップは DCS 座標のみで動く（FR-11） |
| ビーコン（TACAN / ILS）データのライセンスが不明 | 飛行場カードが不完全 | ライセンス確認。難しければユーザー環境で生成するスクリプト方式に切り替える |
| ニーボード画像の推奨サイズ・フォルダ規約が資料により食い違う | 機内で表示されない・歪む | Phase 2 で実機検証し、結果を README に残す |
| DCS 純正 DTC の形式が未公開 | DTC 連携が作れない | 実ファイルの `DTC` キーを継続観察。連携は v1 の範囲外 |
| 地図タイルの利用規約（OSM は大量アクセス制限） | 表示停止 | OpenFreeMap を既定にし、キャッシュとオフラインフォールバックを用意 |
| 公開リポジトリへの個人情報混入（フィクスチャの `.miz` や出力物） | プライバシー | 同梱前に文字列を検査。作者名・パスを含むキーを洗い出す |

## 付録 A. 手元ミッションからの確認事項（2026-09-06）

| 項目 | 確認結果 |
|---|---|
| 本数・マップ | 19 本。Caucasus 5 本、Marianas 14 本 |
| ZIP の中身 | すべて `mission`、`options`、`warehouses`、`theatre`、`l10n/DEFAULT/dictionary`、`l10n/DEFAULT/mapResource` の 6 エントリ。ニーボードやブリーフィング画像の埋め込みは無し |
| `mission` の形式 | UTF-8 の Lua テーブル `mission = { ... }`。最大約 600 KB。ME バージョン 23 |
| Client スロット | 1〜60 機。Player は 1 本のみ 1 機 |
| 登場機種（Client） | F-15ESE、FA-18C_hornet、F-16C_50、F-14A/B、F-4E-45MC、A-10C_2、AV8BNA、AH-64D_BLK_II、Ka-50_3、JF-17、M-2000C、UH-1H、Mi-24P、F-5E-3、C-130J-30、F-15C |

| 敵勢力 | SA-2、SA-6、SA-3 レーダー、Hawk、NASAMS、Strela-1、Shilka、Stinger など SAM / AAA が豊富。脅威リングの検証に十分 |
| ME 描画 | 3 本で `drawings` を使用。レイヤー Red / Blue / Neutral / Common / Author |
| トリガーゾーン | 全本で使用。多角形（`verticies`）も 2 本にあり |
| `DTC` キー | 2026 年作成の 2 本で、航空機グループ直下に `["DTC"] = {}`（空） |
| 機種固有設定 | F-15E: レーザーコード（`Sta2/5/8LaserCode`、`LCFT/RCFTLaserCode`）、`Radio` 20ch プリセット、`datalinks.Link16`、`NavTargetPoints`。F-15C: `STN_L16`、`VoiceCallsignNumber` |
